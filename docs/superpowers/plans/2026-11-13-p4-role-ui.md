# P4 Role-based UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Role-based tab bar with a single Plan tab, landing view by role, and one header ⋯ menu.

**Architecture:** A pure helper `src/tabsByRole.js` decides tier, visible tabs and landing view; `App.jsx` only renders its output. No rules or data changes.

**Tech Stack:** React 18, Vite, Vitest.

**Spec:** `docs/superpowers/specs/2026-11-13-p4-role-ui-design.md`

## Global Constraints

- No change to tab contents, rules or data. Minimal edits in `App.jsx`, revertable per PR.
- `npm run lint:gate` stays ≤ 2 errors / 32 warnings; `npm test`, `npm run typecheck`, `npm run build` green.
- UI labels in English. Each PR opened against `main` after the previous one merges.

## Review Focus

- A user whose stored personal override is `aggregation` or an Owner-only tab must not land on a hidden/missing view.
- localStorage unavailable (private mode): Plan sub-view falls back to `outline`, no crash.
- All-projects mode (`currentId === '__all__'`): landing and Plan switch must not crash when no project is selected.
- View as (impersonation) still shows only My Work.
- Manager in a project without that program loaded: landing must not set a `scopeProgramId` that does not exist.

## PR P4-A — tab bar, Plan switch, landing (branch `feat/p4-a-tabs`)

### Task 1: `src/tabsByRole.js` + tests

**Files:** Create `src/tabsByRole.js`, `tests/unit/tabsByRole.test.js`

**Interfaces (produces):**
- `PLAN_VIEWS = ['mindmap','outline','gantt']`; `isPlanView(view) -> boolean`
- `uiTier({ isOwner, projects, uid }) -> 'owner'|'manager'|'member'` — manager if any project with `__v2.roles` has `programs[*].pmUid|deputyUid === uid` or `workstreams[*].leadUid === uid`.
- `tabsFor(tier) -> Array<{ id, label, group }>` — ids: `plan`, `my-work`, `actions`, `decisions`, `raid`, `portfolio`, `dashboard`, `team-overview`, `briefing`, `credit-report`, `activity`; order and membership exactly per spec §3; `group` is an integer, a divider is drawn when it changes.
- `landingFor({ tier, override, planView, project, uid }) -> { view, scopeProgramId }` — per spec §4; `override` accepted only if `canSeeView(tier, override)`; manager program = first `roles.programs` entry where uid is PM/Deputy, else program containing a WS with `leadUid === uid`, and only if that program exists in `project.programs`; else `null`.
- `canSeeView(tier, view) -> boolean` — plan sub-views map to `plan`.
- `readPlanView() / writePlanView(v)` in `src/uiPrefs.js` (key `afmpt:planView`, try/catch, default `outline`, invalid → `outline`).

Tests: tier for owner / PM / Deputy / Sub-PM / v1-only member; tab id lists for each tier (exact arrays); landing for each tier, override `aggregation` ignored, override `activity` ignored for member, manager program id missing from project → `null`, `project` null → no crash; `readPlanView` with throwing localStorage → `outline`.

### Task 2: wire into `App.jsx`

- Tab bar renders `tabsFor(tier)`; `plan` active when `isPlanView(view)`, click → `setView(readPlanView())`; `briefing` click opens the Briefing dialog (same handler as the old header button); dividers between groups; keep badges, `data-tour` ids (`tab-my-work`, `view-tabs`), impersonation filter.
- Segmented `Mind map | Outline | Gantt` above content when `isPlanView(view)`; click → `setView(v); writePlanView(v)`.
- Landing effect uses `landingFor` (drop `meta.defaultView`); set `scopeProgramId` when returned.
- Remove "Open Aggregation" from the all-projects empty state; remove the Briefing header button; remove `aggregation` from `DEFAULT_VIEW_OPTIONS`; remove the Owner "workspace default" menu entry.
- Verify: `npm test`, `npm run typecheck`, `npm run lint:gate`, build (PowerShell). Commit, push, PR to `main`.
