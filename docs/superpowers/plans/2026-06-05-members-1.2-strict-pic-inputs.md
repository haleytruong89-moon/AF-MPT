# Members 1.2 — Strict PIC inputs Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Bring the three PIC pickers (`PicEditor`, `DecidedByPicker`, `PicPicker`) to a consistent strict-but-friendly input model: email → canonical name on commit, and `PicPicker` no longer silently saves raw free-text on blur.

**Architecture:** One small pure helper `resolvePicValue(input, teamMembers)` placed alongside `deriveTeamMembers` in `src/App.jsx`. Each picker's commit path threads its typed value through that helper. `PicPicker` additionally gains a smart-blur (email match → resolve; single substring match → auto-pick; else save raw + warning chip).

**Tech Stack:** React 18, single `src/App.jsx`. `npm run build` is the gate (no test framework).

**Spec reference:** `docs/superpowers/specs/2026-06-05-members-1.2-strict-pic-inputs-design.md`

```js
// v30.1.2 — Canonicalize a typed PIC value before it's saved into a domain
// field. If the input looks like an email AND a teamMember has that email,
// return the member's name (e.g. 'hattt4@smartosc.com' → 'Hà Trương Thị Thu').
// Otherwise return the input verbatim (trimmed). Returns '' for empty input.
// Pure, idempotent, no throw.
function resolvePicValue(input, teamMembersList) {
  if (input == null) return input;
  const trimmed = String(input).trim();
  if (!trimmed) return trimmed;
  if (trimmed.includes('@')) {
    const lc = trimmed.toLowerCase();
    const match = (teamMembersList || []).find((m) => (m?.email || '').toLowerCase() === lc);
    if (match?.name) return match.name;
  }
  return trimmed;
}
```

- [ ] **Step 2: Replace the `<input>` onBlur (+ add onKeyDown) and add warning chip after dropdown**

Replace the existing `<input ...>` element (around line 9084-9091) with this version. Keep all other props/styles identical — only `onBlur` is replaced and `onKeyDown` is added:

```jsx
      <input
        value={query}
        onChange={(e) => { setQuery(e.target.value); setOpen(true); }}
        onFocus={() => { setFocused(true); setOpen(true); }}
        onKeyDown={(e) => {
          if (e.key === 'Enter' && suggestions[0]) {
            e.preventDefault();
            commit(suggestions[0].name);
          } else if (e.key === 'Escape') {
            e.preventDefault();
            setOpen(false);
            e.currentTarget.blur();
          }
        }}
        onBlur={() => {
          setFocused(false);
          setTimeout(() => setOpen(false), 150);
          const raw = (query || '').trim();
          if (!raw) { onChange(''); return; }
          // 1. Email-typed and a member has that email → canonicalize.
          const resolved = resolvePicValue(raw, teamMembers);
          if (resolved !== raw) { setQuery(resolved); onChange(resolved); return; }
          // 2. Smart-pick: if exactly one teamMember name substring-matches
          //    the raw input (case-insensitive), auto-pick that member.
          //    Avoids ambiguous matches.
          const lc = raw.toLowerCase();
          const subMatches = (teamMembers || []).filter((m) =>
            m?.name && m.name.toLowerCase().includes(lc)
          );
          if (subMatches.length === 1) {
            setQuery(subMatches[0].name);
            onChange(subMatches[0].name);
            return;
          }
          // 3. Fall back: save raw free-text. The warning chip surfaces below.
          onChange(raw);
        }}
        placeholder={placeholder || 'Type a name or email…'}
        style={{ width: '100%', padding: '8px 10px', border: '1px solid ' + (focused ? TOK.lineStrong : TOK.lineStrong), borderRadius: 7, fontFamily: FONT_STACK, fontSize: 12, outline: 'none', background: TOK.surface, color: TOK.ink, boxSizing: 'border-box' }}
      />
```

## Known risks

- **Ambiguous substring**: e.g. "An" matches "An Nguyen" + "An Le" → no auto-pick; user keeps the raw "An" with warning chip. Documented in spec.
- **Email with typo**: extra space, missing `@`, etc. → no email match, no substring match → free-text fallback. Acceptable.
- **`PicEditor` "Use as free text" button** still saves what the user typed (now email-resolved). Future hardening can dim or hide that button when there are matches — not in this plan.
- **`teamMembers` shape consistency**: PicEditor uses `combined` (locally deduped), DecidedByPicker uses `teamMembers` prop directly, PicPicker uses `teamMembers` prop. The resolver treats them uniformly because all three are arrays of `{ name, email }`. Verified by reading each component's local data shape.
