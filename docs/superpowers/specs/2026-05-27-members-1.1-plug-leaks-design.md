# Members — Sub-phase 1.1: Plug identity leaks

## Context

An audit (full report in commit history) found that domain content fields (`task.pic`, `task.contributors`, `task.checkIns[].author`, `task.updates[].author`, `actionItem.pic`, `actionItem.subtasks[].pic`, `decision.decidedBy`, `raid.owner/createdBy/approvedBy/validationOwner/history[].author`, `mitigation.pic`, `project.projectLead`, `weightChangeLog[].by`) store **arbitrary strings** — display name, email, or free-text — with no FK to a canonical identity. Result: the same person can appear under 3 names (Firebase displayName, email, free-text from welcome dialog) and views that group-by-PIC (Activity Dashboard, Credit Report, Workload) double/triple-count them.

This Sub-phase 1.1 (of Phase 1 Hybrid plan A) **stops new fragmentation at the entry points and gives the owner a single-click cleanup for legacy data**. It is the cheapest, highest-value step. Strict pickers (1.2) and unified Members UX (1.3) follow as separate sub-phases.

## Goals

1. **Remove the NameDialog code path entirely.** The dialog still exists as legacy fallback in `App.jsx`. Even though `AuthGate` (auth.tsx) only renders App when Firebase `authUser` is non-null — making the branch effectively dead today — leaving it in keeps a UX-reachable code path that wrote user-typed display names to localStorage and started historic fragmentation. Removing it eliminates the path entirely + simplifies the auth gate.
2. **Extend `performLegacyMerge`** in `ProjectSettingsModal` to rewrite every identity field the merge tool currently misses, so a single "Merge" click consolidates ALL ref to a single canonical name across the project (today the tool leaves RAID fields, subtask PICs, resolvedBy, action update authors silently un-renamed).

## Non-goals (deferred to 1.2 / 1.3)

- Strict PIC pickers / "Did you mean…" warnings (Sub-phase 1.2).
- Consolidating the 3 add-member entry points into one unified UI (Sub-phase 1.3).
- Members audit panel (Sub-phase 1.3).
- Schema migration to email-keyed PIC fields (Phase 2 — deferred).

## Change set

### Part A — Remove NameDialog code path

**Why safe**: `AuthGate` in `src/auth.tsx` gates `<App />` behind `user !== null`. Therefore `authUser` is guaranteed truthy inside App, and the `!author && !authUser → NameDialog` branch is unreachable in production. The auto-derive effect (added earlier this session) populates `author` from `authUser.name`/`authUser.email` automatically. Welcome dialog has no remaining function.

**What to remove from `src/App.jsx`**:
- `function NameDialog(...)` definition (currently ~lines 1913-1935; verify by grep).
- `function SignedOutLanding(...)` if not used elsewhere — verify; remove if only NameDialog referenced it.
- State `const [showNameDialog, setShowNameDialog] = useState(false)` (around line ~7879) and any setters.
- State `const [signedOut, setSignedOut] = useState(false)` (around line ~7878) — only used by the dialog branch.
- `onNameSubmit` handler (around line 7998-8004).
- The auth-gate branch at line ~8324-8338 collapses from:
  ```jsx
  if (!author) {
    if (authUser) { return <loading>; }
    if (signedOut && !showNameDialog) { return <SignedOutLanding ...>; }
    return <NameDialog ...>;
  }
  ```
  to:
  ```jsx
  if (!author) {
    // AuthGate guarantees authUser; show brief loader while the auto-derive effect runs.
    return (
      <div style={{ display: 'flex', alignItems: 'center', justifyContent: 'center', height: '100vh', fontFamily: FONT_STACK, background: TOK.bg, color: TOK.muted, fontSize: 13 }}>
        Signing you in as {authUser?.email || '…'}…
      </div>
    );
  }
  ```
- The sign-out flow at `signOut` (around line 8009-8021) currently calls `setAuthor(null); setAuthorEmail(null);` — keep that (still correct — when Firebase logs out, AuthGate unmounts App). Do NOT need `setSignedOut(true)` anymore.
- localStorage `K.userLocal` cache is RETAINED. It survives reload + serves the legitimate offline-fast-path use case.

### Part B — Extend `performLegacyMerge` to all identity fields

**File**: `src/App.jsx`, function `performLegacyMerge({ from, to, email })` (currently in `ProjectSettingsModal`, around line ~13837-13944).

**Current coverage** (per the audit):
- `task.pic` ✓
- `task.contributors[]` ✓
- `task.creditShares{key}` ✓
- `task.checkIns[].author` ✓
- `task.updates[].author` ✓
- `project.projectLead` ✓
- `project.weightChangeLog[].by` ✓
- `project.decisions[].decidedBy[]` ✓
- `project.actionItems[].pic` ✓
- `project.actionItems[].decidedBy[]` ✓

**Missing coverage to add**:
- `task.updates[].resolvedBy` (set when a blocker is resolved)
- `project.programs[].raid[].owner`
- `project.programs[].raid[].createdBy`
- `project.programs[].raid[].approvedBy`
- `project.programs[].raid[].validationOwner`
- `project.programs[].raid[].history[].author`
- `project.programs[].raid[].mitigationActions[].pic`
- `project.actionItems[].subtasks[].pic`
- `project.actionItems[].updates[].author`
- `project.decisions[].author` (single string, when present)

For each, rewrite-on-match-only: if the stored value (string) equals `from`, replace with `to`. Arrays use `.map` + equality check; nested arrays similarly. Idempotent.

**Confirmation dialog update**: the existing confirm prompt summarizes "Replace X with Y across…" — extend the listed scope to mention RAID + subtasks + action updates so the owner knows the wider sweep. Acceptance criterion includes this string update.

## Acceptance criteria

- [ ] `NameDialog` function and its render branch are deleted from `src/App.jsx`. `grep "NameDialog" src/App.jsx` returns no results.
- [ ] `SignedOutLanding`, `showNameDialog`, `signedOut`, `onNameSubmit` are removed if they have no other consumers (verify each via grep before removal).
- [ ] The auth gate `if (!author)` branch now renders the brief "Signing you in as …" loader; no other dialog/landing.
- [ ] Sign-in (Google) → App loads → no dialog appears at any point. Sign-out (button) → AuthGate sign-in screen appears. Sign-in again → straight back into App, no dialog.
- [ ] `performLegacyMerge` rewrites the 10 newly listed fields (RAID owner / createdBy / approvedBy / validationOwner / history.author, mitigationActions.pic, subtasks.pic, action updates.author, task updates.resolvedBy, decisions.author).
- [ ] After triggering the merge on a project containing legacy references in those fields, `git diff` / a manual scan shows all references for `from` rewritten to `to`. Counter `touched` reflects the count.
- [ ] Confirm dialog wording updated to include "RAID items, mitigations, subtasks, action updates, resolved-by" in the scope.
- [ ] `npm run build` clean.
- [ ] No regression to existing merge behavior for the 10 fields already covered.

## Risks

- **Hidden NameDialog consumer**: if some legacy flow (e.g. a manual "edit my name" menu) still calls `setShowNameDialog(true)`, removing the dialog breaks that. The plan's grep-before-delete step catches it.
- **Merge rewrite mutates many nested arrays**: ensure each rewrite path uses immutable `.map` (the existing tool already does this; new branches must follow the same pattern). Implementer checklist enforces.
- **Activity log not in scope**: activity entries store `author` as email (server-validated by Firestore rules). They are intentionally NOT included in the merge — emails don't change. Documented.
