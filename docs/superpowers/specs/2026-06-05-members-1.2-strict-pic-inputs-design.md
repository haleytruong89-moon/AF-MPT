# Members — Sub-phase 1.2: Strict PIC inputs

## Context

Sub-phase 1.1 plugged the historic identity leak (removed NameDialog) and extended the merge tool to cover RAID + subtask fields. Sub-phase 1.2 closes the remaining live leak: **the three PIC picker components** that still allow new fragmentation at write time.

Current state of the three pickers (audited 2026-06-05):

| Picker | Used by | Free-text warning | Email→name resolve on save |
|---|---|---|---|
| `PicEditor` (App.jsx:2487) | task.pic, action.pic | ✅ chip + "Use as free text" button | ⚠️ only via Enter on filtered dropdown; "Use as free text" path saves raw |
| `DecidedByPicker` (App.jsx:3649) | decision.decidedBy[] | ✅ similar | ⚠️ same partial behavior |
| `PicPicker` (App.jsx:9057) | RAID owner, validationOwner, mitigation.pic | ❌ none | ❌ none — `onBlur` saves raw `query.trim()` |

`PicPicker` is the major leak: type anything, tab away, app silently saves the raw string into `raid.owner` etc. — the exact fields 1.1 just added merge-rewrite for.

## Goal

Make the three PIC pickers consistent and prevent new fragmentation at the entry point:
1. **Bring `PicPicker` to parity** with `PicEditor` (warning chip on unknown value + smart-blur instead of silent raw save).
2. **Email→displayName resolution on commit** in all three pickers (typing a known member's email saves their canonical name, not the email).

Smart-blur behavior (confirmed with requester): if the typed value has exactly one substring-matching candidate in teamMembers → auto-pick that candidate. Otherwise save the trimmed text as free-text (back-compat for RAID owners who legitimately aren't yet in the roster), accompanied by a ⚠ warning chip on the displayed value.

## Non-goals (deferred)

- Fuzzy "Did you mean…" via Levenshtein for typos (1.3).
- Email-prefix heuristic ("hattt4" → suggest member with email starting with "hattt4@…") (1.3).
- Forcing membership before save (rejected during brainstorm — would block legitimate "outsider as RAID owner" cases).
- Unified Members modal (1.3).
- Schema migration to email-keyed PIC fields (Phase 2).

## Design

### New helper: `resolvePicValue(input, teamMembersList)`

Pure function, placed alongside `deriveTeamMembers` in `App.jsx` near line ~1242.

```js
// v30.1.2 — Canonicalize a typed PIC value before it's saved into a domain
// field. If the input looks like an email AND a teamMember has that email,
// return the member's name (so 'hattt4@smartosc.com' → 'Hà Trương Thị Thu').
// Otherwise return the input verbatim. Returns null/empty for empty input.
function resolvePicValue(input, teamMembersList) {
  if (input == null) return input;
  const trimmed = String(input).trim();
  if (!trimmed) return trimmed;
  // Detect email shape
  if (trimmed.includes('@')) {
    const lc = trimmed.toLowerCase();
    const match = (teamMembersList || []).find((m) => (m?.email || '').toLowerCase() === lc);
    if (match?.name) return match.name;
  }
  return trimmed;
}
```

Used at every commit site in the three pickers. Idempotent. No throw on bad input.

### `PicEditor` changes (App.jsx:2487)

- `pick(name)` (line ~2511): wrap with `resolvePicValue(cleaned, combined)` — `combined` is the dedup'd list of members already in scope.
- The existing "Use as free text" button (line ~2570): call `resolvePicValue(draft, combined)` before `onChange(...)`. If the typed value was an email matching a member, the button still saves the member's name (silent normalize — better UX than warning user about something easily fixable).
- No UI change. Behavior change: email-typed PIC always normalizes to canonical name.

### `DecidedByPicker` changes (App.jsx:3649)

- Same treatment: every `commit(name)` / `addToValue(...)` path runs through `resolvePicValue` before adding to the array.
- Filter list is already keyed off teamMembers — same scope variable as before.
- No UI change.

### `PicPicker` changes (App.jsx:9057) — biggest

- **Warning chip on the rendered value** when value doesn't match any teamMember and isn't empty: small ⚠ pill below the input "Not a team member — free-text saved" with a click-to-edit affordance. Match the style of `PicEditor`'s "⚠ Not a team member" chip at line ~2603.
- **Smart blur**: replace
  ```js
  onBlur={() => { ...; onChange(query.trim()); }}
  ```
  with smart logic:
  ```js
  onBlur={() => {
    setFocused(false);
    setTimeout(() => setOpen(false), 150);
    const raw = (query || '').trim();
    if (!raw) { onChange(''); return; }
    // 1. Email-typed and a member has that email → canonicalize.
    const resolved = resolvePicValue(raw, teamMembers);
    if (resolved !== raw) { setQuery(resolved); onChange(resolved); return; }
    // 2. Smart-pick: if exactly one teamMember name substring-matches the
    //    raw input (case-insensitive), auto-pick that member. Avoids
    //    ambiguous matches.
    const lc = raw.toLowerCase();
    const subMatches = (teamMembers || []).filter((m) =>
      m?.name && m.name.toLowerCase().includes(lc)
    );
    if (subMatches.length === 1) {
      setQuery(subMatches[0].name);
      onChange(subMatches[0].name);
      return;
    }
    // 3. Fall back: save raw free-text. The warning chip surfaces below.
    onChange(raw);
  }}
  ```
- The smart-pick rule only fires on **exactly one substring match** (unambiguous). Two-or-more matches keep the raw text — the user can re-open the dropdown to pick.
- Enter-key on the input behaves like clicking the first dropdown item (same convention PicEditor uses at line ~2528).

### Resolver applied symmetrically

Three call paths now route through `resolvePicValue`:

| Picker | Path | Effect |
|---|---|---|
| PicEditor | `pick()` + "Use as free text" button | Email → member name on every commit |
| DecidedByPicker | `commit()` | Same |
| PicPicker | smart-blur Step 1 | Same |

## Acceptance criteria

- [ ] Helper `resolvePicValue(input, teamMembers)` exists in App.jsx, exported as needed within the file.
- [ ] Typing `<existing_member_email>` into any of the three PIC inputs and committing (Enter / Blur / button) saves the member's **name**, not the email.
- [ ] `PicPicker` no longer silently saves arbitrary free-text on blur:
  - Empty input → saves empty (no warning).
  - Email matching a known member → resolves to that member's name.
  - Single substring match → auto-picks that member.
  - Zero or multiple matches → saves raw trimmed text + ⚠ warning chip rendered below the input.
- [ ] Warning chip ("⚠ Not a team member — free-text saved") appears on `PicPicker` when value is non-empty and doesn't match any teamMember name. Clicking chip refocuses the input for correction.
- [ ] No breaking changes to `PicEditor` or `DecidedByPicker` UI; the only behavior change is email→name normalization on commit.
- [ ] Existing `task.pic`, `action.pic`, `decision.decidedBy[]`, `raid.owner`, `mitigation.pic`, `raid.validationOwner` values from before this change are unaffected (no migration).
- [ ] `npm run build` clean.

## Risks

- **Substring auto-pick ambiguity**: if a project has two members "An Nguyen" and "An Le", typing "An" → 2 substring matches → no auto-pick → user re-selects via dropdown. Documented behavior.
- **Case sensitivity for email match**: `resolvePicValue` lowercases both sides. Edge case: a typoed email (extra space) won't match — falls back to raw text + warning chip on PicPicker. Acceptable.
- **PicEditor's "Use as free text" button** still exists (back-compat). It silently resolves email→name now but otherwise saves what the user typed. Future hardening (1.3 Did-you-mean) can further reduce free-text use.
- **No effect on already-stored fragmentation**: this is a forward-looking guard. To clean existing fragmented data, owner uses the merge tool extended in 1.1.

## What's still possible to fragment after 1.2

- Direct free-text in `PicPicker` when there are zero substring matches AND the user doesn't pick from the dropdown (e.g. typing an outsider's name). This is intentional — RAID owners can be non-members. Warning chip surfaces this.
- Free-text via PicEditor's "Use as free text" button when no email match. Same trade-off.
- Manual `task.pic` edits via legacy Excel import or rare paths not flowing through the pickers. Out of scope (covered by merge tool).
